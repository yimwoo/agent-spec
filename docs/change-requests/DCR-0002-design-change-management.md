## Summary

Establish a first-class **Design Change Request (DCR)** intake protocol so
that design updates arriving *after* implementation has started flow through
a single, auditable lane: drafted → assessed for impact → classified
(`implement-now` / `defer` / `spike` / `reject` / `needs-adr`) → linked to
requirements → and only then converted into task context packs.

## Motivation

The current design doc (`D-11.4 Dogfood Mode`) says AgentSpec "records design
changes as ADRs." That conflates two distinct steps:

1. **Intake and impact assessment** of an incoming change (DCR's job).
2. **Decision recording** for an architectural choice that emerges from it
   (ADR's job).

In practice, the user has just handed me two design changes (this very
exercise), and there is no canonical artifact for capturing them. Without a
DCR lane:

- Source-section traceability degrades — there's no anchor for the change.
- Context packs risk being created from unconfirmed assumptions, violating
  goal D-03.1 / R-009 ("Generate implementation tasks only when the relevant
  requirements are sufficiently specified").
- Dogfood Mode (D-11.4) cannot honestly close the loop on its own promise.

DCR-0002 is the workflow that makes DCR-0001 (and every future change) safe
to receive.

## Proposed Change

1. Add `docs/change-requests/` as a first-class artifact directory with a
   README, a canonical DCR shape, and at least one example (this DCR plus
   DCR-0001 satisfy that bootstrapping).
2. Define a five-value classification enum: `implement-now`, `defer`,
   `spike`, `reject`, `needs-adr`.
3. Define DCR status lifecycle: `open → classified → accepted | superseded |
   rejected`.
4. Require every DCR to declare:
   - source-section references it touches (existing `D-*` anchors)
   - impacted existing requirements
   - impacted existing task context packs
   - impacted spec docs and code modules
   - new open questions raised
   - proposed new requirements (recorded with status
     `proposed-pending-acceptance` until DCR is accepted)
   - disposition with rationale and required follow-ups
5. Encode the rule: **a task context pack derived from a DCR must cite the
   DCR ID**, and may not be created until the DCR is classified
   `implement-now` (or `needs-adr` *and* the ADR is accepted).
6. Encode the rule: **requirements introduced by a DCR are recorded as
   `proposed-pending-acceptance`** and only flip to `accepted` when the
   DCR is accepted.
7. Add `docs/change-requests/` to `agentspec init`'s artifact layout (a
   one-line code change, captured as a follow-up context pack, not done
   inline in this intake).
8. Provide a future CLI surface: `agentspec dcr create | classify | accept |
   list` (deferred to a follow-up context pack — schema first, CLI after).

The protocol itself is recorded in `ADR-0002-design-change-protocol.md`.

## Proposed new requirements

All recorded with `status: proposed-pending-acceptance`. They flip to
`accepted` when this DCR is accepted (which the user signaled in the
disposition below).

- `R-121` (P0) — AgentSpec captures every post-implementation design change
  as a DCR document in `docs/change-requests/` before any artifact
  downstream of it is changed.
- `R-122` (P0) — Each DCR is classified as one of: `implement-now`,
  `defer`, `spike`, `reject`, `needs-adr`.
- `R-123` (P0) — A task context pack derived from a DCR must cite the DCR
  ID and may not be created until the DCR is classified `implement-now`,
  or `needs-adr` with the ADR accepted.
- `R-124` (P1) — Requirements introduced by a DCR are recorded with status
  `proposed-pending-acceptance` and only flip to `accepted` when the DCR
  is accepted.
- `R-125` (P1) — The CLI provides `agentspec dcr create | classify | accept
  | list` commands.
- `R-126` (P1) — Drift checker recognizes files derived from a DCR-driven
  context pack and includes the DCR ID in compliance reports.

## Disposition

**Recommended classification: `implement-now` for the process and minimal
artifact schema; `needs-adr` for the protocol decision (ADR-0002 captured
in this same intake).**

Implemented immediately by this intake:

- `docs/change-requests/` directory with README and DCR template shape.
- DCR-0001 and DCR-0002 themselves (which exercise the artifact and prove
  it is usable).
- `ADR-0002-design-change-protocol.md` recording the decision.
- Six proposed requirements (R-121..R-126) recorded with status
  `proposed-pending-acceptance` in `docs/traceability/requirements.yml`.
- Two new open questions (Q-015, Q-016).

**Not** implemented in this intake (deferred to follow-up context pack

- The one-line addition to `agentspec/init.py` so future `agentspec init`
  runs scaffold `docs/change-requests/`.
